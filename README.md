# SSO frontend

React/TypeScript account, subscription commerce and permission-scoped administrative UI, served exclusively through the same-origin HTTPS gateway. The repository is a real API client, not a demonstration shell. It requires the identity, profile, notification, audit/admin, catalog, billing, subscription and referral owners in the approved generic-platform design. Task acceptance uses an isolated origin such as `https://localhost:18448`; the existing `https://localhost:8448` installation is separate.

Own original platform frontend/template code is licensed under MIT (`LICENSE`). Third-party dependencies keep their original licenses and notices; this does not relicense their code.

## Reproducible build

Node **22.22.1**, npm **11.19.0**; exact direct dependencies and npm lockfile. Maintained standards client `oauth4webapi` **3.8.8**, Vite **8.3.5**, Vitest **5.0.5**. Run from Linux/WSL:

```sh
npm ci --ignore-scripts --no-audit
npm test
npm run build
docker build -t sso-frontend:local .
```

If WSL inherits a Windows `npm` on PATH, use the native Linux node explicitly: `node /mnt/c/nvm4w/nodejs/node_modules/npm/bin/npm-cli.js ci --ignore-scripts`, `node node_modules/vitest/vitest.mjs run`, `node node_modules/typescript/bin/tsc`, `node node_modules/vite/bin/vite.js build`. Do not let a Windows npm process choose platform-specific packages for a Linux build.

Container bases are pinned by immutable multi-platform digests (Node 22.22.1 Alpine3.23; nginx-unprivileged 1.30 Alpine). Container serves port **8080** as UID/GID 101. Gateway service port 80 must target 8080. Mount `/tmp` writable when running with a read-only root filesystem; nginx writes PID/temp files there. `GET /health/live` checks nginx, `/health/ready` requires the built index. TLS terminates at the gateway. Frontend itself does not proxy backend routes: a gateway routing error produces HTTP 404, not a successful HTML response masquerading as JSON.

`npm run dev` is for component development only. Start the local platform gateway first, then run `SSO_CA_FILE=../platform-infra/.local/ca.crt npm run dev` from this repository (or supply an absolute CA PEM path). The CA file is required only by the development server, not tests, builds or preview. Development `/api`, `/oauth` and `/.well-known` requests proxy to the actual `https://localhost:8448` gateway with explicit CA and hostname verification, bounded timeouts and no TLS bypass. The proxy changes the upstream Host but preserves the browser Origin: it does not bypass server Origin/CSRF checks or rewrite Secure cookies. Read-only discovery is available at `http://localhost:3000/.well-known/openid-configuration`; its issuer remains `https://localhost:8448`. Complete cookie mutations/OIDC acceptance must use the real HTTPS gateway, configured issuer and registered callback, not insecure Vite port 3000. The test suite uses local HTTP fixtures only at the outbound transport boundary, real API client/form components, and cryptographically signed RSA identity tokens with a real JWKS endpoint; it is not a substitute for deployed integration acceptance.

## User-visible behavior

- Registration with optional referral code and selected locale, email confirmation, password login with MFA challenge, TOTP/recovery codes, authoritative cookie sessions and server logout. Password reset and reauthentication retain the existing security handling.
- Account overview composes the owner API's bounded partial sections. Unavailable sections remain unavailable, never invented empty subscriptions or zero balances. Profile/settings separate website and notification locale; EN/RU switching preserves unfinished forms and never changes identity.
- Catalog purchase and checkout/order recovery distinguish provider pending, payment accepted, fulfillment pending, fulfilled and review. Only authoritative subscription state describes access. Explicit renewals, cancel-at-period-end/resume, expiring upgrade quotes and scheduled downgrade use current versions and immutable offer/action IDs; there is no wallet auto-charge.
- The paid-period boundary invalidates a displayed entitlement allow immediately and triggers a fresh authoritative check. Pending or unavailable rechecks never keep claiming current access; hidden views discard the stale allow while deferring network reads until visible. No local timer grants access.
- Public and administrative catalog readers use `/api/v1/catalog/pages` and `/api/v1/admin/catalog/pages`, iterating opaque cursors through all independently paged streams before publishing a complete view. Each page is checked against `CatalogPage`; the accumulated history has no 1000-record truncation. Aborts or repeated cursors fail visibly rather than presenting partial success. Page traversal is not a globally atomic catalog snapshot; a normal refresh obtains current state.
- Own subscription/payment history and details, referral code, exact USDT-string balances/debt, payout reservations and cancellation. Payout decisions record external transfers; the application never sends funds or promises automatic refunds.
- Referral commands retain the same idempotency identity for an unchanged financial operation after an ambiguous response; definite completion or an explicitly changed command starts a new identity. Latest-read generations and mutation fences prevent delayed refresh/history pages from replacing a completed payout or cancellation with older balances or statuses. These browser safeguards supplement, never replace, the owner's ledger/version checks.
- Security lists device/session activity and expiry; individual, other-session and all-session revocation are separate commands. HTTP 401 clears account-scoped UI; focus, online and visible-tab checks refresh authority. Account transitions unmount scoped state and in-memory secrets.
- Security also lists the signed-in user's connected OAuth applications, approved scopes, trust policy and grant/activity timestamps, with opaque cursor pagination. Own revocation uses the existing cookie/CSRF transport without a staff/MFA gate, waits for the owner reply, then refreshes the authoritative list. Failed lists never become empty success, failed revokes retain the application row, and session changes abort/discard old grant reads. No token or secret is displayed.
- Telegram linking requires bot candidate plus explicit confirmation in the initiating website session. Unlink remains pending until bot confirmation. Missing provider credentials render unavailable, not simulated delivery.
- Administrative user records expose a reasoned, explicitly confirmed Telegram binding reset only with `notifications:bindings:reset` and current admin MFA. The direct profile-owner command accepts the authoritative selected user ID and reason only—never a chat ID—and displays success only after `{status:"reset"}`. Account changes abort and discard pending feedback; the UI does not invent a binding version or a new link.
- Own/admin notification history keeps the established array body and reads the opaque `X-Next-Cursor` header through the original secure transport. Missing header means the end; the browser never derives a timestamp cursor or assumes a full page implies more. Composite owner cursors preserve deliveries sharing the same creation timestamp.
- OWNER role/permission assignments and OAuth client/consent lifecycle; ADMIN catalog revisions/preview/publication/archive, payment review/manual evidence, frozen subscription compensation/close, referral rates/payout decisions, localized notification templates/replay and audit. SUPPORT sees only permitted safe read surfaces and ordinary-user session revocation. Every backend owner remains the authorization authority; role labels alone grant nothing.
- Staff session revocation requires `users:sessions:revoke`, fresh MFA and a reason, through the persisted administrative command journal: SUPPORT targets ordinary users only; ADMIN targets ordinary/non-OWNER staff; OWNER may target any account, including itself. These target-scope controls do not expand ban permissions or replace backend admission checks. Unknown command outcomes retain their idempotency key for recovery.
- Command status refresh is observational. Requested/unknown commands can be explicitly resumed through a CSRF-protected POST using the same journal ID and original actor/mutation permission; the server checks current authority before deciding whether the stored operation may be dispatched. A GET never restarts a mutation.
- Compact dark keyboard-accessible EN/RU layout with 390px forms, localized stable API errors and no raw provider evidence/errors displayed to ordinary users.

### Public owner configuration

`public/config.json` is fetched as inert same-origin JSON, not executable JavaScript. Shape: `{ "brand": { "name": "Account Platform", "logo_url": "", "help_url": "" }, "locales": ["en", "ru"], "default_locale": "en", "canonical_origin": "https://localhost:18448" }`. `canonical_origin` may be omitted to use the current origin; an explicit value must exactly match it. Logo URLs must be same-origin HTTPS; help URLs HTTPS without embedded credentials. No API origin/token/secret is configurable here. The deployment owner renders/mounts this file for `PUBLIC_ORIGIN`; branding/integration credentials are operator deployment settings, not a fictitious live secret-editing screen. Browser language selects the pre-login website locale, followed by the authenticated persisted website locale. Notification locale remains independent.

New frontend regressions cover session ownership, consent boundaries, language/form preservation, permission-scoped render branches, accepted-versus-fulfilled states, checkout/quote commands, compensation conflicts, payout and Telegram pending states. Tests/build/lint/browser acceptance for the 2026-10-24 generic expansion are controller-owned and must be recorded separately; historical evidence below does not establish acceptance of these additions.

### Checked public wire contracts

`src/generated/businessv1.ts` and `validation.ts` are copied from the pinned `platform-contracts/gen/typescript` generator output, with byte hashes in `contracts-types.sha256`. After an approved contract change run `node scripts/sync-contracts.mjs ../platform-contracts` before the frontend checks; do not hand-edit generated sources. `src/wire.ts` selects the exact registered method/path, validates command bodies and owner responses, and rejects duplicate JSON keys. Unregistered existing identity/OIDC endpoints keep their original wire handling. `ApiClient` remains the only business transport and preserves same-origin cookies, CSRF bootstrap, session-generation checks, redirect rejection, abort and the combined 15-second deadline. A schema failure is a localized unavailable/error state, never a fake successful checkout.

## Browser security

Browser auth uses `sso_session` HttpOnly/Secure cookies. No access/refresh tokens enter localStorage, the DOM, URLs or application logs. Mutations bootstrap `/api/v1/auth/csrf` and send `X-CSRF-Token`; requests use same-origin credentials, reject redirects and expire after 15 seconds. Cookies and session ownership are enforced by identity, not the SPA. `return_to` accepts only the exact same-origin `/oauth/authorize` path, rejecting other origins, credentials, fragments, backslashes and control characters. This continues the real standard login redirect without an open redirect.

nginx delivers a restrictive CSP: external same-origin scripts/styles/connect only, no inline/eval, no objects/frames, no third-party resources, and no referrer. React renders server content as text. Do not relax this policy to make injected scripts work. Avatar URL is stored as profile data, never rendered as arbitrary remote content.

The static frontend disables inherited nginx access logs: default combined logging would expose recovery-token queries. Request-level native error logs also go to `/dev/null`, because nginx appends unsanitized request URIs on filesystem/request errors and cannot redact them via `log_format`. Process/configuration startup failures remain available on stderr. Sanitized request access logs and status telemetry belong to the gateway, without duplicate raw-URI logging at this layer.

Password-reset links render even while an account is signed in; their token is removed from history immediately and the document also declares `no-referrer`. An authoritative session change remounts all account-scoped panels, discarding the previous account's profile/admin caches and MFA setup secrets. Logout, expiry and session changes clear the OIDC context. Generation ownership prevents an outstanding authorization/refresh response from restoring tokens after they were cleared. The consumer additionally requires the platform's `token_use: id` claim on every newly issued ID token, rejecting a signed access JWT substituted into the ID-token field.

API responses and pending CSRF bootstrap belong to the session that started them: delayed failures cannot expire a newer account or run an old queued mutation with its credentials. Password-reset completion discards scoped UI/OIDC state and rechecks the actual cookie session. Resetting another account does not claim to log out an unrelated live session; resetting the current account returns to login after the server confirms its revocation.

Only the current authoritative session check can finish its loading boundary; a superseded pre-reset response cannot expose a login form while reset reconciliation is still pending. Explicit session expiry ends that boundary and presents login immediately.

## Actual OIDC consumer

Open **OIDC-потребитель → Начать OIDC-вход**, logged in or logged out. Public client **web-demo**, exact callback **https://localhost:8448/oidc/callback**. The library performs discovery with exact issuer verification, state, PKCE S256, nonce, RS256 algorithm pinning, ID token issuer/audience/timestamps, **explicit JWKS signature verification**, and matching UserInfo `sub`. The proof view shows validated public claims, not raw tokens. Refresh is a real `refresh_token` grant with rotation, signature/claim and subject continuity checks. Refresh calls are single-flight; any failure clears tokens. Fresh ID tokens on refresh cannot change authenticated subject/issuer/audience/auth_time/nonce. An omitted refresh ID token retains the already validated identity and verifies UserInfo again.

Only a 10-minute, consumed-once PKCE/state/nonce transaction crosses the authorization redirect in sessionStorage; tokens remain in memory. Reloading the proof page intentionally discards tokens and requires a new authorization. Callback query is removed from browser history, including errors. No unsigned JWT decoder or client secret is shipped.

The exact `/oauth/consent` path is the React consent screen and must route through the gateway to this static frontend. Both nginx layers special-case only that path; `/oauth/authorize`, `/oauth/token`, and `/oauth/consent/complete/{id}` remain identity-owned. Unknown OAuth/API paths must not fall back to successful SPA HTML.

## CI

The repository verification workflow uses SHA-pinned checkout/setup-node, locked installs with npm auditing disabled, ESLint JavaScript/TypeScript recommended correctness rules plus React hook-order enforcement (`npm run lint`), deterministic Prettier validation (`npm run format:check`), behavioral tests, TypeScript/production build, secret scans and an immutable commit-SHA local container build. All quality tools are exact-version locked. Use `npm run format` for an intentional one-time formatting update; CI only checks, never rewrites. No image push, deployment or cloud operation is configured. Security reports are not uploaded as artifacts. Vulnerability scanning is disabled by policy; removing those gates does not establish an absence of vulnerabilities.
Push, PR and manual-dispatch runs use the same verification path. Complete Git history is scanned first with digest-pinned Gitleaks and redacted output; checkout credentials are not persisted. Both CI and the Docker builder explicitly install npm 11.19.0 rather than relying on Node 22.22.1's bundled npm 10.9.4. Trivy is digest-pinned and used only for working-tree secret scanning; its raw secret report stays in the disposable runner directory rather than logs or uploaded artifacts. The separate immutable container build does not export a scanner-only image archive. First publication uses push/PR checks because manual dispatch requires the workflow to exist on the default branch.
The digest-pinned Nginx runtime receives signed Alpine v3.24 security packages at exact versions: `musl` and `musl-utils` **1.2.6-r3**, `zlib` **1.3.2-r1**. Alpine's security database maps these revisions to CVE-2026-107891 and CVE-2026-85091. Package installation runs as root only during the image build; the final process remains uid/gid 101. Missing pinned packages fail the build; no findings, metadata or inventories are removed. Existing patched dependencies and images remain pinned.
