# Generic platform frontend implementation plan

Goal: real EN/RU account, checkout, subscription, referral and permission-scoped administration UI against the owning public APIs, preserving existing cookie/CSRF/OIDC security.

Constraints: frontend-only isolated worktree; no publication/deployment/provider transfers. Backend authoritative authorization. Money remains decimal strings. No test/build/lint/format execution in this worker; parent executes regression and browser acceptance after integration.

## Files and delivery
1. Add `src/i18n.tsx`, `src/resources.ts`, `src/i18n.test.tsx`: typed EN/RU resource registry, pre-login browser locale, independent persisted website locale, localized stable error codes, exact-string USDT display. Language changes preserve mounted form/session state.
2. Extend `src/api.ts` with PUT and Accept-Language without changing generation/CSRF/abort handling. Add `src/platform.ts`, `src/platform.test.ts`: agreed domain DTOs, paginated reads, cancellable visible-page refresh, stable idempotent command keys and explicit accepted-versus-fulfilled rendering.
3. Add `src/CommercePanel.tsx`, `src/ReferralPanel.tsx`, `src/OverviewPanel.tsx`, behavioral regressions: public catalog purchase, own checkout/history/details, renewal/upgrade quote/downgrade/cancel/resume; partial overview unavailable never empty success; referral balance/payout request/cancel.
4. Replace scoped existing account/profile/security UI with resource-key translations and authoritative session refresh; add `src/ConsentPanel.tsx` for same-session OAuth consent. Keep OIDC cryptographic implementation and secure memory handling unchanged.
5. Extend administration with focused `src/CatalogAdmin.tsx`, `src/CommerceAdmin.tsx`, `src/IdentityAdmin.tsx`, `src/NotificationAdmin.tsx`: permission-scoped server-backed catalog lifecycle, payment review/evidence, frozen compensation previews/close, rates/payout decisions, OWNER role/permission/OAuth, templates/delivery replay, SUPPORT ordinary-session revoke only. Exact request/response contracts come from owner API inventories, never guessed.
6. Integrate navigation in `src/App.tsx`; compact accessible 390px dark layout in `src/index.css`; update existing README/changelog. Report changed interfaces and unexecuted commands in `local://generic-frontend-report.md`.

## Regressions authored before implementation
- Locale switch preserves form input and never calls identity mutation; stable API codes render localized messages without raw provider payload.
- PAYMENT_ACCEPTED/FULFILLMENT_PENDING never render active access, only FULFILLED does.
- Stale requests from previous session cannot repopulate account data; unmount aborts reads; hidden tabs do not refresh.
- Support cannot render finance mutations/role changes; owner permission editor uses expected_version/reason and one-time OAuth secret can be cleared.
- Consent requires explicit approve/deny and rejects unsafe redirect targets.
- Cancel/resume/renew/upgrade quote use displayed subscription version and authoritative response, never locally fabricate period/access.

## Parent commands
`npm ci`; `npm test`; `npm run build`; `npm run lint`; `npm run format:check` (format only in final integration if needed). Browser Relay: EN/RU user/OWNER/ADMIN/SUPPORT at desktop/390px, account switch/logout, permission denied/unavailable/pending/expiry paths and real provider gates from approved design.

## Finalized implementation interfaces
Resource dictionaries are feature-local `identity-resources.ts`, `account-resources.ts`, `commerce-resources.ts`, `admin-commerce-resources.ts` rather than one mixed global dictionary. Shared domain adapters live in `commerce.ts`, with canonical DTO aliases from copied `src/generated/businessv1.ts`; `wire.ts` validates registry commands/responses while preserving the original secure transport. `scripts/sync-contracts.mjs` records exact authoritative generated bytes; `scripts/verify-contracts.mjs` is enforced by CI/Docker. `.prettierignore` protects byte provenance of generated files only. The repository had no changelog; existing README is updated as the permanent feature documentation. Public brand/help/locale configuration is inert JSON operator deployment configuration; no invented runtime secret/settings mutation API.
